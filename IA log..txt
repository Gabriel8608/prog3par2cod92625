## Idea del proyecto: **"Mi Catálogo de Productos"**

Una app Android donde el usuario explora un catálogo de productos, ve sus precios en distintas monedas, lee publicaciones relacionadas y guarda sus favoritos con notas personales. Cada una de las tres APIs cumple un papel claro dentro de la app.

**DummyJSON** → *Pantalla principal (Catálogo)*
- Es la fuente del catálogo. De aquí salen los productos que el usuario ve: imagen, nombre, categoría, descripción y precio en dólares.

**Frankfurter** → *Pantalla de detalle (Conversión de moneda)*

**JSONPlaceholder** → *Pantalla de detalle (Publicaciones/Reseñas)*

# Guía práctica: DummyJSON, Frankfurter y JSONPlaceholder

Las tres APIs permiten hacer solicitudes HTTPS sin una clave. DummyJSON y JSONPlaceholder entregan datos de muestra para practicar; Frankfurter ofrece tipos de cambio de referencia, que se actualizan diariamente. [Documentación de DummyJSON](https://dummyjson.com/docs/products), [Frankfurter](https://frankfurter.dev/) y [JSONPlaceholder](https://jsonplaceholder.typicode.com/)

## 1. DummyJSON: productos

**Endpoint:** `GET https://dummyjson.com/products`

La respuesta es un objeto con `products` —una lista— y los metadatos `total`, `skip` y `limit`. La documentación muestra 30 productos por defecto. [Ejemplo y esquema oficial](https://dummyjson.com/docs/products)

| Campo | Tipo | Descripción |
|---|---|---|
| `id` | entero | Identificador |
| `title`, `description`, `category` | texto | Nombre, descripción y categoría |
| `price`, `discountPercentage`, `rating` | número decimal | Precio, descuento porcentual y valoración |
| `stock`, `weight`, `minimumOrderQuantity` | entero | Inventario, peso y cantidad mínima |
| `tags` | lista de textos | Etiquetas |
| `brand`, `sku`, `availabilityStatus` | texto | Marca, código SKU y estado |
| `dimensions` | objeto de decimales | `width`, `height`, `depth` |
| `reviews` | lista de objetos | Valoración, comentario, fecha y datos de quien reseña |
| `meta` | objeto | Fechas de creación y modificación, código de barras y QR |
| `thumbnail` | texto | URL de miniatura |
| `images` | lista de textos | URLs de imágenes |

Respuesta abreviada:

```json
{
  "products": [
    {
      "id": 1,
      "title": "Essence Mascara Lash Princess",
      "category": "beauty",
      "price": 9.99,
      "discountPercentage": 7.17,
      "rating": 4.94,
      "stock": 5,
      "tags": ["beauty", "mascara"],
      "thumbnail": "...",
      "images": ["..."]
    }
  ],
  "total": 194,
  "skip": 0,
  "limit": 30
}
```

**Parámetros y rutas útiles**

- Paginación: `?limit=10&skip=10`. `limit=0` solicita todos los productos.
- Selección: `?select=title,price`.
- Búsqueda: `/products/search?q=phone`.
- Categoría: `/products/category/smartphones`.
- Orden: `?sortBy=title&order=asc`.
- La documentación también incluye filtros por fecha de modificación mediante `modifiedAfter` y `modifiedBefore`.

Al crear, editar o borrar, las respuestas simulan la operación; los cambios no se guardan en el servidor. [Detalles de paginación, filtros y operaciones](https://dummyjson.com/docs/products)

## 2. Frankfurter: tipos de cambio USD → EUR y BOB

**Endpoint solicitado:** `GET https://api.frankfurter.dev/v2/rates?base=USD&quotes=EUR,BOB`

En v2, `/rates` devuelve una **lista de filas**, no un objeto con un mapa `rates`. Cada fila contiene:

| Campo | Tipo | Significado |
|---|---|---|
| `date` | texto `YYYY-MM-DD` | Fecha de la cotización |
| `base` | texto | Moneda base, por ejemplo `USD` |
| `quote` | texto | Moneda cotizada, por ejemplo `EUR` o `BOB` |
| `rate` | decimal | Unidades de `quote` por cada unidad de `base` |

Ejemplo de estructura documentada —los valores dependen de la fecha consultada—: [documentación oficial de Frankfurter](https://frankfurter.dev/)

```json
[
  {"date": "2026-07-03", "base": "USD", "quote": "EUR", "rate": 0.87598},
  {"date": "2026-07-03", "base": "USD", "quote": "BOB", "rate": 6.9}
]
```

`BOB` es el código de moneda boliviano; revisa la respuesta real para confirmar que el endpoint devuelve ambas filas en la fecha disponible. Las cotizaciones no necesariamente corresponden al día calendario actual, porque los datos se actualizan diariamente y dependen de la publicación de las fuentes.

Parámetros principales:

- `base=USD`: define la moneda base.
- `quotes=EUR,BOB`: limita las monedas objetivo.
- `date=YYYY-MM-DD`: consulta una fecha.
- `from=YYYY-MM-DD&to=YYYY-MM-DD`: consulta un intervalo histórico.
- `providers=ecb`: filtra por proveedor; por defecto los valores pueden combinar fuentes.

No requiere clave. No tiene un endpoint de conversión: calcula `monto × rate`. Son tasas de referencia, no cotizaciones de compraventa en tiempo real. La API documenta errores HTTP `400`, `404` y `422` con un cuerpo JSON con `status` y `message`. [Parámetros, formatos y errores](https://frankfurter.dev/)

## 3. JSONPlaceholder: publicaciones

**Endpoint:** `GET https://jsonplaceholder.typicode.com/posts`

La respuesta es una lista de 100 publicaciones. [Guía oficial y respuesta de ejemplo](https://jsonplaceholder.typicode.com/)

| Campo | Tipo | Descripción |
|---|---|---|
| `userId` | entero | ID del usuario autor |
| `id` | entero | ID de la publicación |
| `title` | texto | Título |
| `body` | texto | Contenido; puede incluir saltos de línea |

Ejemplo real de la primera publicación:

```json
{
  "userId": 1,
  "id": 1,
  "title": "sunt aut facere repellat provident occaecati excepturi optio reprehenderit",
  "body": "quia et suscipit\nsuscipit recusandae consequuntur expedita et cum\nreprehenderit molestiae ut ut quas totam\nnostrum rerum est autem sunt rem eveniet architecto"
}
```

Rutas y consultas útiles:

- Una publicación: `/posts/1`
- Filtrar por autor: `/posts?userId=1`
- Comentarios asociados: `/posts/1/comments` o `/comments?postId=1`

La guía oficial muestra filtros y rutas anidadas. Para reducir resultados al paginar, JSONPlaceholder también admite los parámetros habituales `_start` y `_limit`, por ejemplo `/posts?_start=0&_limit=10`. Las operaciones `POST`, `PUT`, `PATCH` y `DELETE` son simuladas: las respuestas aparentan aplicar el cambio, pero este no queda guardado. [Guía oficial](https://jsonplaceholder.typicode.com/)

## Android con Kotlin y Retrofit

Con Retrofit, crea un servicio por API porque cada una tiene un dominio base distinto. En Android, declara el permiso de Internet en el manifiesto:

```xml
<uses-permission android:name="android.permission.INTERNET" />
```

Modelos mínimos para las respuestas:

```kotlin
data class ProductPage(
    val products: List<Product>,
    val total: Int,
    val skip: Int,
    val limit: Int
)

data class Product(
    val id: Int,
    val title: String,
    val description: String,
    val category: String,
    val price: Double,
    val discountPercentage: Double,
    val rating: Double,
    val stock: Int,
    val thumbnail: String,
    val images: List<String>
)

data class Rate(
    val date: String,
    val base: String,
    val quote: String,
    val rate: Double
)

data class Post(
    val userId: Int,
    val id: Int,
    val title: String,
    val body: String
)
```

Interfaces Retrofit:

```kotlin
interface DummyJsonApi {
    @GET("products")
    suspend fun products(
        @Query("limit") limit: Int = 30,
        @Query("skip") skip: Int = 0
    ): ProductPage
}

interface FrankfurterApi {
    @GET("v2/rates")
    suspend fun rates(
        @Query("base") base: String = "USD",
        @Query("quotes") quotes: String = "EUR,BOB"
    ): List<Rate>
}

interface JsonPlaceholderApi {
    @GET("posts")
    suspend fun posts(
        @Query("_start") start: Int = 0,
        @Query("_limit") limit: Int = 10
    ): List<Post>
}
```

Configura cada instancia de Retrofit con su propio `baseUrl`:

- DummyJSON: `https://dummyjson.com/`
- Frankfurter: `https://api.frankfurter.dev/`
- JSONPlaceholder: `https://jsonplaceholder.typicode.com/`

Llama a las funciones `suspend` desde una corrutina, por ejemplo en `viewModelScope.launch`. Maneja errores de red y HTTP, y considera que una respuesta válida puede traer una lista vacía. Para Frankfurter, convierte con `amount * rate`; para dinero, conserva la precisión decimal adecuada y redondea solo al presentar el resultado.

**Paginación:** en DummyJSON usa el `skip` de la siguiente página (`skip + limit`) y verifica `total`; en JSONPlaceholder incrementa `_start` hasta que la API devuelva una lista vacía o una lista menor que el límite solicitado.

- [Frankfurter: documentación v2](https://frankfurter.dev/)

    val id: Int,                 // mismo id del producto de DummyJSON
    val title: String,
    val priceUsd: Double,
    val thumbnail: String,
    val note: String = ""        // nota personal del usuario
)

Relaciones:
  - No hay relaciones foráneas. Tabla independiente y autocontenida.
  - El "id" coincide con el id del Product de DummyJSON, lo que permite saber
    si un producto ya está guardado (evita duplicados).


================================================================================
(b) DISEÑO DE LA BASE DE DATOS
================================================================================

Motor: Room (SQLite)
Nombre de la BD: app_database
Versión: 1

--------------------------------------------------------------------------------
Tabla: favorite_products
--------------------------------------------------------------------------------

+----------------+---------+------------------------------------------+---------+
| Columna        | Tipo    | Descripción                              | Clave   |
+----------------+---------+------------------------------------------+---------+
| id             | INTEGER | Id del producto (viene de DummyJSON)     | PK      |
| title          | TEXT    | Nombre del producto                      |         |
| priceUsd       | REAL    | Precio en USD al momento de guardar      |         |
| thumbnail      | TEXT    | URL de la imagen principal               |         |
| note           | TEXT    | Nota personal del usuario (puede vacía)  |         |
+----------------+---------+------------------------------------------+---------+

Clave primaria: id (INTEGER, NO autogenerada; se toma del producto original).

Decisiones de diseño:
  - id no es autogenerado: se reutiliza el id del producto de DummyJSON para
    evitar duplicados (un producto solo puede estar una vez en favoritos).
  - priceUsd se guarda como REAL para conservar el precio histórico.
  - note se guarda como TEXT con valor por defecto "".
  - No se guarda la tasa de cambio: es volátil y se consulta en vivo.

Operaciones previstas sobre la tabla (DAO):
  - Obtener todos los favoritos como Flow<List<...>>  (observable en la UI)
  - Insertar o reemplazar un favorito (OnConflictStrategy.REPLACE)
  - Eliminar un favorito por id (@Query DELETE)
  - Actualizar la nota de un favorito
  - Verificar si un producto ya es favorito (por id)

Estados de la pantalla de Favoritos:
  - Lista con elementos -> se muestra el listado.
  - Lista vacía          -> se muestra "Sin elementos guardados".


================================================================================
(c) CAPAS DE MVVM Y SU CONTENIDO
================================================================================

El proyecto sigue el patrón MVVM con separación en capas: data (remota + local +
repositorio), domain (modelos) y ui (pantallas + ViewModels).

--------------------------------------------------------------------------------
C.1 CAPA DATA (data/)
--------------------------------------------------------------------------------

data/remote/dummyjson/
  - ProductDto, ProductsResponseDto
  - DummyJsonApi   -> @GET("products") suspend fun products(limit, skip): ProductsResponseDto

data/remote/frankfurter/
  - RateDto
  - FrankfurterApi -> @GET("v2/rates") suspend fun rates(base, quotes): List<RateDto>

data/remote/jsonplaceholder/
  - PostDto
  - JsonPlaceholderApi -> @GET("posts") suspend fun posts(_start, _limit): List<PostDto>

data/remote/
  - RetrofitInstances -> una instancia de Retrofit por baseUrl:
        * DummyJSON:       https://dummyjson.com/
        * Frankfurter:     https://api.frankfurter.dev/
        * JSONPlaceholder: https://jsonplaceholder.typicode.com/

data/local/
  - FavoriteProductEntity  -> entidad de Room
  - FavoriteProductDao     -> DAO con Flow y suspend
  - AppDatabase            -> base de datos con instancia única (singleton)

data/repository/
  - CatalogRepository   -> llama a DummyJsonApi, mapea ProductDto -> Product.
                           Devuelve Result<List<Product>>.
  - CurrencyRepository  -> llama a FrankfurterApi, recibe List<RateDto>, busca
                           las filas EUR y BOB y construye ExchangeRates.
                           Devuelve Result<ExchangeRates>.
  - PostRepository      -> llama a JsonPlaceholderApi, mapea PostDto -> Post.
                           Devuelve Result<List<Post>>.
  - FavoriteRepository  -> operaciones CRUD sobre Room (favoritos).

Todos los repositorios devuelven Result<T> y manejan errores (red, HTTP no
exitosa, excepciones). Aquí se hace el mapeo DTO -> modelo de dominio.

--------------------------------------------------------------------------------
C.2 CAPA DOMAIN (domain/)
--------------------------------------------------------------------------------

  - Product
  - ExchangeRates
  - Post
  - FavoriteProduct

Modelos puros, sin dependencias de Retrofit ni Room.

--------------------------------------------------------------------------------
C.3 CAPA UI (ui/)
--------------------------------------------------------------------------------

ui/screens/
  - CatalogScreen        -> lista de productos + buscador + acceso a Publicaciones
  - ProductDetailScreen  -> detalle + conversión de moneda + "Marcar favorito"
  - PostsScreen          -> lista de publicaciones (pantalla independiente)
  - FavoritesScreen      -> lista de favoritos + quitar + mensaje de lista vacía

ui/viewmodel/
  - CatalogViewModel
      * UiState: Loading / Success(products) / Error(message)
      * StateFlow<CatalogUiState>
      * query como StateFlow + derivedStateOf para filtrar
      * acción: reintentar()
  - ProductDetailViewModel
      * UiState del producto
      * UiState de las tasas (Loading / Success(ExchangeRates) / Error)
      * acciones: cargarTasas(), marcarFavorito()
  - PostsViewModel
      * UiState: Loading / Success(posts) / Error(message)
      * acción: reintentar()
  - FavoritesViewModel
      * observa el Flow de favoritos de Room
      * acción: quitarFavorito(id)
      * expone si la lista está vacía para el mensaje "Sin elementos guardados"

ui/theme/ y MainActivity -> punto de entrada y tema.

--------------------------------------------------------------------------------
C.4 FLUJO DE DATOS (resumen)
--------------------------------------------------------------------------------

  Pantalla (Compose)
        |
        v
  ViewModel (UiState + StateFlow)
        |
        v
  Repository (Result<T>, mapeo DTO -> dominio)
        |
        +--> API remota (Retrofit + DTO)
        +--> Room (Entity + DAO)

  - La UI solo observa StateFlow y llama funciones del ViewModel.
  - El ViewModel nunca llama a Retrofit ni a Room directamente: siempre pasa
    por el repositorio.
  - El repositorio es el único que conoce DTOs, entidades y APIs.
